# 课程多元评价平台 · 接口文档（测试依据）

> ## 本文档的用途
>
> **这是编写接口/功能测试用例的唯一接口事实来源。**
>
> 配合《课程多元评价平台操作手册》使用，两者分工：
>
> | | 提供什么 |
> |---|---|
> | **本接口文档** | 接口层面的事实：方法、路径、参数、响应、**错误码**、业务规则边界 |
> | **操作手册** | 界面与业务流程：什么角色、在什么场景、点哪里、期望看到什么 |
>
> **两者交叉，即为测试用例的输入。**
>
> ### ⚠️ 写用例前必读
> 第 **4 节**列出「手册说了、代码里没有或不一致」的条目。
> **这些不能按手册直接写正向用例**——否则会测到根本不存在的功能，用例必然失败且原因难查。
>
> 例如：手册说"忘记密码可自助找回"，但后端**没有任何找回接口**；
> 手册说排课冲突会显示"冲突"标记，但后端**没有冲突检测**。
>
> ### 适用范围

> 未挂载的死代码（`tasks.js`、`extra.js` 的 notes/student-tiers）**不在测试范围内**，详见 §3.9。

## 1. 测试前置约定

### 1.1 服务地址与端口

```
http://<host>:<port>/api
```

⚠️ **联调前必须先对齐端口，否则所有用例都会因连接失败而"全红"**：

| | 默认端口 | 来源 |
|---|---|---|
| 后端服务 | **3000** | `server/index.js` `PORT` |
| 前端请求 | **3002** | `src/api/index.ts` `VITE_API_PORT` |

任选其一对齐：`PORT=3002 npm start`（在 `server/` 下）或 `VITE_API_PORT=3000 npm run dev`。
也可用 `VITE_API_BASE` 直接指定完整地址。

### 1.2 鉴权与角色

**Header**：`Authorization: Bearer <token>`（JWT，HS256，有效期 **7 天**）

**JWT 载荷**：`{ id, account, name, role, sub_role }`

| role | sub_role | 中文角色 | 登录后门户 |
|---|---|---|---|
| `admin` | — | 管理员 | `/admin/schedules` |
| `teacher` | `teacher` | 教师 | `/teacher/courses` |
| `teacher` | `mentor` | 企业导师 | `/mentor/courses` |
| `teacher` | `leader` | 学院领导 | `/leader/courses` |
| `student` | — | 学生 | `/student/courses` |

> 企业导师与学院领导**共用 `role='teacher'`**，靠 `sub_role` 区分。测试身份切换时注意这一点。

**全局鉴权规则**：

- **GET / OPTIONS 一律放行**，不校验 token。→ **读接口人人可调**，这是需要覆盖的既有行为。
- 其余方法（POST / PUT / PATCH / DELETE）必须带合法 token，否则 `401`。
- 免登录白名单：`/api/user/login`、`/api/auth/login`、`/api/health`。

**角色守卫（本次测试重点）**：

| 守卫 | 放行谁 | 用在哪 |
|---|---|---|
| `requireAdmin` | 仅 `admin` | `/api/accounts/*` + 6 类管理资源的**写路由** |
| `requireStaff` | `admin` / `teacher` / `leader` / `sub_role=mentor` —— 即**教职工，学生不可** | `/api/schedules` 的**写路由** |
| **无守卫** | 任何登录用户 | 全部**教学类**路由（`/api/eval`、`/api/teaching`、`/api/quality-evaluations`、`/api/tier-test`、`/api/projects`、成绩配置） |

> **必须覆盖的权限矩阵**（详见 §3 各接口的鉴权列）：
> - 学生调管理类写接口 → **403**
> - 教师调管理类写接口 → **403**（课程/学生/学院等）
> - 教师调**排课**写接口 → **放行**（教师端"新建课程内班级"会自动补写排课，收紧会打断它）
> - 未登录调任何写接口 → **401**

### 1.3 两套响应格式（两个不同的前端解析器）

后端存在两种响应包装，**由两个不同的前端请求函数消费**，测试断言时不要混淆：

**格式一 · `success` 布尔**（绝大多数接口）

```json
{ "success": true, "message": "登录成功", "token": "…" }
{ "success": false, "message": "账号或密码错误（还剩 4 次机会）" }
```

消费者：`src/api/index.ts` 的 `request()`。判定失败的条件是 `!response.ok || data.success === false`。

**格式二 · `code/msg/data`**（仅 `/api/projects` 全族 + `/api/course-standards` + `/api/questionnaire`）

```json
{ "code": 200, "msg": "success", "data": { } }
```

消费者：`src/api/knowledgeGraph.ts` 的 `javaRequest()`。判定失败的条件是 `!response.ok || data.code !== 200`，错误文案取 `data.msg`。

> ⚠️ 这**不是缺陷**——两个包装器分工明确。但测试时要知道：调用格式二的接口，即使 `code: 500`，HTTP 状态码也是非 200，两个解析器都能识别。
> **没有任何接口返回 HTTP 200 却带 `success:false` 或 `code!=200`。**

### 1.4 统一错误码

| HTTP | 场景 | 典型 body |
|---|---|---|
| 400 | 参数缺失 / 格式错误 | `{ success:false, message:"手机号格式不正确（需 11 位）" }` |
| 401 | 未登录 / token 失效 / 密码错 | `{ success:false, message:"账号或密码错误（还剩 4 次机会）" }` |
| 403 | 账号被禁用 / **角色不足** | `{ success:false, message:"无权限执行该操作" }` |
| 404 | 资源不存在 | `{ success:false, message:"账号不存在" }` |
| 409 | 唯一性冲突 / 状态冲突 | `{ success:false, message:"该手机号已被其他账号使用" }` |
| 413 | 请求体过大 | `{ code:413, msg:"上传内容过大…", data:null }` |
| 423 | **账号锁定**（密码连错 5 次，锁 15 分钟） | `{ success:false, message:"账号已锁定，请 N 分钟后再试", code:"ACCOUNT_LOCKED" }` |
| 429 | **限流**（仅小智接口） | `{ success:false, message:"请求过于频繁，请稍后再试" }` |
| 500 | 服务器内部错误 | `{ success:false, message:"服务器内部错误" }` |

### 1.5 上传与体积限制 ⚠️ 四层限制，别记错

**文件一律以 base64 塞在 JSON body 里**（课程标准、项目资料、素质评价附件、头像），base64 会膨胀约 1/3。

| 层 | 真实限制 | 何时生效 |
|---|---|---|
| **前端校验** | **文件 ≤ 720 KB，且一次上传各文件合计 ≤ 720 KB** | **正常操作最先拦住**——测试时通常只会撞到这一层 |
| nginx | 请求体 1 MiB（`client_max_body_size` 默认值，未配置覆盖） | 绕过前端直接调接口时 |
| Express | 请求体 2 MB | **设计上永不触发**（刻意架在 nginx 之上，避免变成隐藏瓶颈） |
| MySQL | `max_allowed_packet` | 后端启动时自检并告警 |

**720 KB 是算出来的，不是拍脑袋**（`src/lib/uploadLimits.ts`）：

```
nginx 上限 1,048,576 字节 − 保留 65,536（JSON 结构/字段名/转义/中文文件名）
→ 可用 983,040 ÷ 4 × 3（base64 反推）≈ 737,280 字节 = 720 KB
```

> ⚠️ **单文件上限与合计上限是同一个值（720 KB）**，`MAX_UPLOAD_FILE_SIZE === MAX_UPLOAD_TOTAL_SIZE`。
> 界面上也直接写着这个数（如学生端素质评价："单个文件 ≤ 720KB，合计 ≤ 720KB"）。
>
> ⚠️ **手册§四·六 写的"单个文件不超过 2MB"是错的**（见 §4）。
>
> ⚠️ `uploadLimits.ts` 的注释记录过同类事故：曾"文案承诺 5MB、实际约 760KB 才传得上去"。
> 教训是——**必须从网关上限反推文件上限**，反过来推会算出比网关还大的值。

**其余限制**：

- 超限的响应：前端**直接拦截并提示**（不发请求）；若绕过前端，nginx/Express 返回 `413`。
- 头像单独限制：base64 长度 > 400 KB → `400 头像过大`。

### 1.6 初始密码与密码规则

- **初始密码**：身份证号**后 6 位**，末位 `X` 转大写，保留前导 0。
- **新密码规则**：**≥ 8 位，且同时包含字母和数字**，否则 `400`。
- 学生/教师/企业导师/学院领导**首次登录强制改密**（`need_change_password=1`），管理员不触发。

> ⚠️ **与手册不一致**：手册的账号表示例密码是 `666666/222222/555555/443333`，但**代码里没有产生固定密码的任何逻辑**（唯一出处是导出时身份证解密失败的兜底值）。这些是历史数据，不是规则。测试初始密码必须按"身份证后 6 位"构造。

## 2. 接口契约

### 2.1 健康检查与认证

#### GET `/api/health` — 健康检查（公开）

响应：`{ "status": "ok", "time": "2026-…Z" }`
注意：**不返回 `success` 字段**，与项目约定不一致。

#### POST `/api/user/login` — 统一登录（公开，推荐）

```json
{ "account": "202600034", "password": "555555" }
```

`account` 可为**手机号**或**学号/工号**。

成功 `200`：

```json
{
  "success": true, "message": "登录成功", "token": "eyJ…",
  "user": { "account": "138…", "name": "张三", "department": "大数据学院",
            "role": "student", "sub_role": "", "isTeacher": false, "userNo": "202600034" },
  "portal": "/student/courses",
  "need_change_password": true
}
```

**必须覆盖的异常分支**：

| 条件 | 期望 |
|---|---|
| 账号或密码错 | `401`，message 含**剩余尝试次数** |
| 连续错 5 次 | `423`，`code:"ACCOUNT_LOCKED"`，锁定 15 分钟 |
| 账号 `status='inactive'` | `403`，`该账号已被禁用` |
| `need_change_password=1` | 登录成功但 `need_change_password: true`，前端应跳改密页 |

> 学院领导额外返回 `asTeacher` / `asMentor`（是否兼任教师/导师）。

#### POST `/api/auth/login` — 学生专用登录（公开，旧接口）

请求 `{ "studentId": "…", "password": "…" }`。查 `students` 表。

> ⚠️ 它签发的 JWT 里 `id` 是 **students 表主键**；而 `/api/user/login` 的 `id` 是 **users 表主键**。**两套 id 空间不同**，混用会查错人。新用例请统一用 `/api/user/login`。

#### GET `/api/auth/verify` — 校验 token

需 Header 带 Bearer。成功返回 `{ success:true, user:{…} }`；token 过期 `401`；账号被禁用 `403`。

#### POST `/api/user/change-password` — 修改密码（需 JWT）

```json
{ "newPassword": "abc12345", "oldPassword": "555555" }
```

- `oldPassword` **可省略**（省略即首登强制改密场景，跳过旧密码校验）。
- 违反密码规则 → `400`（分两种 message：`新密码至少 8 位` / `新密码需同时包含字母和数字`）。
- 传了 `oldPassword` 但不正确 → `400 旧密码不正确`。

#### GET `/api/user/profile` — 个人信息（需 JWT）

响应 `{ success:true, profile:{ name, userNo, phone, department, role, subRole, roleLabel, className, email, status, avatar } }`
`roleLabel` 由 role+sub_role 推导：管理员 / 学生 / 企业导师 / 学院领导 / 教师。

#### POST `/api/user/change-phone` — 修改绑定手机号（需 JWT）

```json
{ "newPhone": "13900000000", "password": "当前密码" }
```

| 条件 | 期望 |
|---|---|
| 手机号不符合 `^1\d{10}$` | `400` |
| 当前密码错 | `400 当前密码不正确` |
| 新号与当前相同 | `400` |
| 新号已被他人占用 | `409` |

成功后**同步更新** `users.account` 与 `students.phone` / `teachers.phone`。

#### POST `/api/user/avatar` — 上传头像（需 JWT）

`{ "avatar": "data:image/png;base64,…" }`。空值 → `400`；base64 > 400 KB → `400 头像过大`。

### 2.2 账号管理（管理员）

> 全部挂在 `/api/accounts`，**受 `requireAdmin` 保护**。**非管理员必须 403**。

#### POST `/api/accounts/students` — 单个学生入库

```json
{ "name": "张三", "phone": "13800000000", "idCard": "510000200001011234",
  "department": "大数据学院", "className": "大数据2301" }
```

自动：查重身份证/手机号 → 派发学号 → 生成初始密码（身份证后 6 位）→ 写 `users` + `students`。

`201` 响应：`{ success:true, account:{ id, userNo, account, name, role, subRole, refType, refId, initialPassword } }`

| 条件 | 期望 |
|---|---|
| 姓名空 | `400 NAME_REQUIRED` |
| 手机号非 11 位 | `400 PHONE_FORMAT` |
| 身份证非 18 位 | `400 ID_CARD_FORMAT` |
| 身份证已入库 | `409 ID_CARD_EXISTS`（message 含已有学号/工号） |
| 手机号已入库 | `409 PHONE_EXISTS` |

#### POST `/api/accounts/teachers` — 单个教师/导师/领导入库

```json
{ "name": "李四", "phone": "13800000001", "idCard": "510000199001011234",
  "subRole": "mentor", "department": "大数据学院" }
```

`subRole` 取值 `teacher`（默认）/ `mentor` / `leader`，其它值 → `400 IDENTITY_UNKNOWN`。派发工号形如 `2026T00026`。

#### 学号/工号派发规则

- 教师类：`{年份}T{5位序号}` → `2026T00026`
- 学生类：`{年份}{5位序号}` → `202600035`

并发安全（`account_sequences` 表）。**可用例：并发创建多个账号，学号不应重复。**

#### GET `/api/accounts` — 账号列表

| 参数 | 说明 |
|---|---|
| `keyword` | 模糊匹配 姓名 / 手机号 / 学号工号 |
| `role` | `admin` / `teacher` / `student` |
| `refType` | `student` / `teacher` |
| `status` | `active` / `inactive` |
| `page` | 默认 1 |
| `pageSize` | 默认 20，**上限 100**（传 200 应被压到 100） |

响应 `{ success:true, total, page, pageSize, accounts:[…] }`，每项含 `initial_password`（明文）。

#### PUT `/api/accounts/:id/status` — 启用 / 禁用

`{ "status": "active" }` 或 `{ "status": "inactive" }`。其它值 → `400 INVALID_STATUS`。id 不存在 → `404`。

#### PUT `/api/accounts/:id/password` — 重置密码

无请求体。效果：密码恢复为身份证后 6 位，且 `need_change_password = 1`（下次登录强制改密）。

#### PUT `/api/accounts/:id/assign` — 分配学院 / 班级

`{ "department": "大数据学院", "className": "大数据2301" }`。同步更新 `users.department` 与 `students.department / class_name`。

#### DELETE `/api/accounts/:id` — 删除账号

级联删除 `students` 或 `teachers` 关联记录后删除 `users` 行。id 不存在 → `404`。

#### POST `/api/accounts/import` — 批量导入

```json
{ "rows": [
  { "name":"张三","phone":"138…","idCard":"510…","identity":"学生","department":"大数据学院","className":"大数据2301" },
  { "name":"李四","phone":"139…","idCard":"510…","identity":"企业导师","department":"大数据学院" }
] }
```

`identity` 映射表（**必须逐项覆盖**）：

| 输入 | 映射为 |
|---|---|
| 学生 / student / 学 / 生 | `role=student` |
| 教师 / teacher / 老师 / 师 | `role=teacher, sub_role=teacher` |
| 企业导师 / mentor / 企导 / 导师 | `role=teacher, sub_role=mentor` |
| 学院领导 / leader / 领导 / 院领导 | `role=teacher, sub_role=leader` |
| 其它任何值 | `400`，计入该行错误 |

**逐行容错**——单行失败不影响其它行：

```json
{ "success": true, "results": { "inserted": 8, "failed": 2,
  "errors": [ { "row": 3, "name": "王五", "message": "身份证已入库（学号/工号 202600020）" } ] } }
```

**用例**：混入 1 行非法身份 + 1 行重复身份证，确认 `inserted` 数正确、`errors` 定位到正确行号。

#### GET `/api/accounts/export` — 导出全部账号

身份证**已脱敏**为 `******`，**不含**初始密码。

#### GET `/api/accounts/export-students` — 导出全部学生

含**明文** `初始密码`（列名为中文：`学号`/`姓名`/`手机号`/`学院`/`状态`/`初始密码`）。

#### GET `/api/accounts/export-teachers` — 导出全部教师

含**明文** `初始密码`，`身份` 字段转为中文（教师/企业导师/学院领导）。

### 2.3 基础数据

> **写路由全部 `requireAdmin`**。GET 全部公开。

#### 学院 departments

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/departments` | 公开 | 列表（含专业数/课程数/班级数/学生数/教师数统计） |
| POST | `/api/departments` | **Admin** | `{ name, color? }`；重名 → `409` |
| PUT | `/api/departments/:id` | **Admin** | 改名/改色，同步关联表冗余字段；重名 → `409`；不存在 → `404` |
| GET | `/api/departments/:id/usage` | 公开 | 删除前影响面预览（**不执行删除**） |
| DELETE | `/api/departments/:id` | **Admin** | 见下方两段式规则 |

**删除学院的两段式规则（重点用例）**：

1. `GET /:id/usage` → 返回 `{ usage, hasData }` 影响面统计。
2. `DELETE /:id`（学院下有数据时）→ **`409 DEPARTMENT_HAS_DATA`**，body 带 `details` 影响面。
3. `DELETE /:id?force=true`（或 body `{force:true}`）→ **级联删除全部关联数据，不可逆**。
4. `DELETE` 一个空学院 → 直接 `200`。

#### 学生 students

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|

#### 排课 schedules

> **鉴权例外：写路由是 `requireStaff`（教职工可写），不是仅管理员。**
> 原因：教师端"新建课程内班级"会自动补写一条排课，收紧会打断该流程。
> **用例**：教师写排课 → 放行；学生写排课 → `403`。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/schedules?class=&courseId=` | 公开 | 列表 |
| POST | `/api/schedules/bulk` | **Staff** | 批量导入（去重规则见下） |
| PUT | `/api/schedules/:id` | **Staff** | 更新单条 |
| DELETE | `/api/schedules/:id` | **Staff** | 删除单条 |

**GET 响应**：

```json
{ "success": true, "schedules": [
  { "id": "17", "courseId": "cs-101", "title": "算法与数据结构", "teacher": "李四",
    "mentor": "王五", "semester": "2026-2027-1", "room": "A301", "className": "大数据2301",
    "day": "3", "startDate": "2026-09-01", "endDate": "2027-01-10", "timeSlot": "3-4" } ] }
```

**批量导入** `POST /api/schedules/bulk`：

```json
{ "schedules": [ { "courseId":"cs-101", "title":"算法与数据结构", "startDate":"2026-09-01",
  "endDate":"2027-01-10", "timeSlot":"3-4", "room":"A301", "teacher":"李四",
  "mentor":"王五", "day":"3", "semester":"2026-2027-1", "className":"大数据2301" } ] }
```

⚠️ **班级字段语义（关键测试点）**：`className` 为空 **= 全班级**，对本课程所有学生生效。

| 场景 | 期望行为 | 计数 |
|---|---|---|
| 已有"全班级"行，再导入任意（带或不带班级） | **跳过** | `coveredByGlobal++`, `skipped++` |
| 导入"全班级"行，但该时段已有班级专属行 | **跳过**（否则每班凭空多一节课） | `shadowedByClass++`, `skipped++` |
| **同班**重复导入 | **更新**该行 | `updated++` |
| **不同非空班级**同时段 | 合法并行班，**插入**新行 | `inserted++` |
| 缺 `title` 或 `startDate` 或 `timeSlot` | 跳过 | `skipped++` |

响应：

```json
{ "success": true,
  "message": "成功导入 12 条，更新 3 条，跳过 2 条（2 条已由全班级排课覆盖）",
  "inserted": 12, "updated": 3, "skipped": 2, "coveredByGlobal": 2, "shadowedByClass": 0 }
```

**副作用**：导入时若 `courses` 表无该课程会**自动创建**；若 `teachers` 表无该教师会**自动创建教师**。

⚠️ **PUT 的 `className` 特殊规则**：只有请求体里**显式包含 `className` 键**（哪怕值为 `null`）才覆盖；不传则保留库中原值。
**用例**：只改 `room` 不传 `className` → 该排课的班级归属不变（不能从"某班专属"变成"全班级"）。

⚠️ **冲突检测不存在**：手册说的"重复排课显示冲突标记"后端**没有实现**（见 §4）。

#### AI 分层测试

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tier-test/:courseId/questions` | 取题目（**首次调用触发生成，慢，超时设 60s**） |

| GET | `/api/tier-test/:courseId/result/:studentId` | 查询某生结果 |

**取题**：首次无缓存 → 调大模型生成 10 道题 → 存库 → 返回。**响应不含正确答案**。

**提交**：

```json
{ "studentId":"202600034", "answers":[ { "questionId":"q1", "answerText":"选项原文" } ] }
```

⚠️ **`answerText` 必须传"选项原文"**（不能传 `"A"` 或序号）。后端判分做了归一化容错，**这些容错点都是用例**：

- 忽略空格、大小写、中英文标点。
- 判断题在 `正确/错误`、`对/错`、`true/false`、`T/F`、`√/×` 之间**互相等价**。
- 若 AI 把答案写成 `"B"` / `"选项B"` / `"2."`，会按序号取回选项原文再比一次。

**层级判定（总分 100 分制）**：

| 总分 | tier | tierLabel |
|---|---|---|
| ≥ 80 | `excellent` | 卓越层 |
| ≥ 60 | `advanced` | 进阶层 |
| < 60 | `basic` | 基础层 |

响应：

```json
{ "success":true, "score":85, "tier":"excellent", "tierLabel":"卓越层",
  "details":[ { "questionId":"q1", "isCorrect":true, "score":10,
                "correctAnswer":"…", "studentAnswer":"…" } ] }
```

**特殊用法（用例）**：

| 输入 | 期望 |
|---|---|
| `answers: []`（空数组） | **自动分配层级**，跳过判分（用于课程还没出题） |
| 同一学生重复提交 | 返回 `alreadySubmitted: true` + 原结果（**不覆盖**） |
| 学生不存在 | `404 学生不存在` |
| 无题目且非自动分配 | `400 还没有分层测试题目` |

> ⚠️ 响应 `details` 里**回传了 `correctAnswer`**——学生提交后能看到全部正确答案。
> ⚠️ 手册说"第一节课结束后才开启测试"，但**后端没有闸门**，闸门在前端。**直接调 API 可绕过时间限制。**

**用例**：只传姓名的导入行 → 应匹配失败。**Excel 导入必须有学号/手机号/身份证。**

#### 素质评价的角色差异

企业导师端"素质评价"为**只读**（手册§五），对应 `PUT .../score` 是教师行为。

### 2.7 待办

> 用户私有数据。**`created_by` 由服务端从 JWT 注入，不接受前端传参。**

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/todos` | 登录 | 当前用户的全部待办（此接口是 GET，**自行解析 token**，无 token → `401`） |
| POST | `/api/todos/sync` | 登录 | 全量对账：删除该用户不在列表中的行 + 替换列表中的行（事务） |

**GET 响应**：

```json
{ "success": true, "todos": [
  { "id":"todo-…", "title":"…", "completed":false,
    "createdAt":"2026-10-15", "dueDate":"", "createdBy":"张三" } ] }
```

**sync 请求体**：`{ "todos": [ …同上结构… ] }` → 响应 `{ success:true, synced: N }`。

**用例（重点）**：

| 条件 | 期望 |
|---|---|
| `GET /api/todos` 无 token | **`401`**（不能退化成"返回全表"） |
| `POST /api/todos/sync` 无 token | `401` |
| `todos` 不是数组 | `400` |
| 传了 `createdBy` 想读别人的 | **无效**——服务端忽略该字段，只返回自己的 |
| 两次 sync 传入不同列表 | 第二次的列表成为最终状态（覆盖式） |
| 传无 `id` 或无 `title` 的行 | 被丢弃，不计入 `synced` |

### 2.8 AI 助手「小智」

#### GET `/api/assistant/health` — 公开

```json
{ "success":true, "status":"configured", "apiKeyConfigured":true, "lastDecision":{…}, "boot":{…} }
```

`status` 为 `misconfigured` 时表示大模型密钥未配好，前端会降级到"本地兜底"。

#### POST `/api/assistant/navigate` — **需登录 + 限流**

⚠️ **此接口已不再是公开接口**（此前在免登录白名单里，会导致任何人空烧大模型额度）。

| 条件 | 期望 |
|---|---|
| 无 token | **`401`** |
| 已登录 | `200` |
| 同一用户 1 分钟内超过 **20 次** | **第 21 次起 `429`** |

请求体：`AssistantAgentRequest`（见 `src/lib/assistantAgent.ts`），前端超时 30s。
成功响应：`{ success:true, …决策结果（跳转目标、思路摘要、来源标记） }`
失败：`{ success:false, code:"assistant_error", diagnostics:…, message:"智能体暂时不可用" }`

## 4. 与操作手册的差异（写用例前必读）

**以下条目不能按手册直接写正向用例**，否则会测到不存在的功能。

| 手册章节 | 手册说法 | 代码实际 | 对用例的影响 |
|---|---|---|---|
| §一 账号表 | 初始密码 `666666/222222/555555/443333` | 代码只按"**身份证后 6 位**"生成，无固定密码逻辑 | 初始密码用例必须用身份证后 6 位构造，不能用示例值 |
| §1.3 / FAQ Q4 | "忘记密码？"可自助找回 | **后端无任何找回接口** | ❌ **不要写自助找回用例**。忘记密码只能走管理员重置 |
| §九 排课 | 重复排课显示"冲突"标记 | **后端无冲突检测** | ❌ **不要写冲突标记用例**。可写"重复排课的去重计数"（见 §2.3 排课） |
