# Apifox 接口测试 · 零基础操作手册

> **这份文件是写给"完全没用过 Apifox、也不懂接口"的人看的。**
> 你不需要懂代码、不需要懂 HTTP。**照着做，一步一步来。**
>
> 配套文件：`docs/apifox-课程多元评价平台接口测试.json`

---

## 开始之前：你需要什么

| 需要 | 说明 |
|---|---|
| 一台能上网的电脑 | —— |
| Apifox 软件 | 官网 <https://www.apifox.cn> 下载，注册一个账号（免费） |
| 5 个账号的"登录名 + 密码" | 管理员、教师、企业导师、学院领导、学生，**各一个** |

> ⚠️ 如果某个角色的账号密码你不知道：**先找管理员要**。没有账号就没法测那一部分。
> 管理员默认账号通常是 `admin`，密码见你们的部署文档。

## 第一步：导入测试集合（约 2 分钟）

1. 打开 Apifox，登录。
2. 点左上角的 **「项目」**，进入任意一个项目（没有就点「新建项目」起一个）。
3. 在左侧栏最下面找到 **「导入数据」**（也可能显示为「导入」或一个 ↑ 箭头图标）。
4. 弹出窗口里，选择 **「Postman」** 这个来源。
5. 点 **「选择文件」**，找到并选中：
   ```
   docs/apifox-课程多元评价平台接口测试.json
   ```
6. 点 **「确定 / 导入」**，等几秒。

**导入成功后你应该看到左边出现 12 个文件夹：**

```
📁 00 登录（先跑这个）
📁 01 变量准备（先跑这个）
📁 02 测试数据准备（先跑这个）
📁 TC-AUTH 权限与鉴权（25 条）
📁 TC-COM 通用流程（11 条）
📁 TC-ADM 管理员端（46 条）
📁 TC-TCH 教师端（14 条）
📁 TC-STU 学生端（7 条）
📁 TC-E2E 端到端（1 条）
📁 TC-BND 边界与异常（12 条）
📁 TC-DIFF 已知差异（8 条）
📁 99 危险操作（谨慎，默认勿一键运行）
```

> ❗ **看不到这些文件夹？** 说明导入没成功。重新做第 3–6 步，注意第 4 步一定要选 **Postman**，不是 OpenAPI/Swagger。

## 第二步：填写账号密码（约 5 分钟）⭐ 最重要

导入后，很多请求里写着 `{{teacherAccount}}` 这种**带双大括号的东西**——这是"变量"。
**不填就会测试失败。**

### 2.1 方式一（推荐）：导入现成的环境文件

1. Apifox 左侧栏 → **「环境管理」**（齿轮图标）→ **「导入」**。
2. 选择文件：
   ```
   docs/apifox-环境-课程多元评价平台.json
   ```
3. 导入后会出现一个叫 **「课程多元评价平台（线上）」** 的环境。
4. **在右上角的下拉框里选中这个环境**（这一步最容易被忘）。

### 2.2 方式二：手动新建环境（导入失败时用）

1. Apifox 左侧栏 → **「环境管理」** → **「新建环境」**，命名随意（如"线上测试"）。
2. 在「变量」表格里，**点「添加」逐个加**下面这张表的变量：

| 变量名（必须一字不差） | 值填什么 | 例子 |
|---|---|---|
| `baseUrl` | 网站地址，**不要带结尾斜杠，不要带 `/api`** | `http://47.114.42.189` |
| `adminAccount` | 管理员登录名 | `admin` |
| `adminPassword` | 管理员密码 | `666666` |
| `teacherAccount` | 教师登录名（工号） | `2026T00026` |
| `teacherPassword` | 教师密码 | 身份证后 6 位 |
| `mentorAccount` | 企业导师登录名（工号） | `2026T00027` |
| `mentorPassword` | 企业导师密码 | 身份证后 6 位 |
| `leaderAccount` | 学院领导登录名（工号） | `2026T00028` |
| `leaderPassword` | 学院领导密码 | 身份证后 6 位 |
| `studentAccount` | 学生登录名（学号） | `202600034` |
| `studentPassword` | 学生密码 | 身份证后 6 位 |
| `studentPhone` | 学生手机号 | `13800000000` |
| `deptName` | 学院名称 | 吉林省医药中等职业学校 |

> **其余变量不用加**（`adminToken`、`deptId`、`testCourseId` 等），程序会自动写入。
> 先跑「00 登录」时若报"变量不存在"，把这些空变量也补上（值留空即可）：
> `adminToken` `teacherToken` `mentorToken` `leaderToken` `studentToken`
> `deptId` `categoryId` `courseId` `studentId`
> `testDeptId` `testCategoryId` `testCourseId` `targetUserId`
> `fakeId`（值填 `999999`）`runId`（值留空）`className`（值填 `APITEST班`）
> `teacherName`（值填 `APITEST教师`）`bigBase64`（值留空）

### 2.3 保存并选中

1. 点 **「保存」**。
2. **看右上角的环境下拉框，确认选中的是你刚建/刚导入的环境。**
   - 没选中 = 变量全空 = 所有请求失败。这是新手最常见的坑。

> 💡 **不知道密码？** 让管理员在系统「账号管理」页找到该账号 → 点「重置密码」。
> 重置后是**身份证后 6 位**（不是 `666666` 那种固定值）。
>
> 💡 表里的数字都是**举例**，请填你自己的。

## 第三步：运行（按顺序，不要跳）

### 3.1 先跑「00 登录」

1. 左侧点开 **「00 登录（先跑这个）」**。
2. 看到 5 个请求（管理员/教师/企业导师/学院领导/学生）。
3. **鼠标移到文件夹名上 → 右边出现「运行」按钮（▶）→ 点它**。
4. 右边会打开「运行」面板，**不要改任何设置**，直接点 **「运行」**。
5. 等它跑完，看结果：

**✅ 全部绿色 = 成功。** 这时 5 个角色的"通行证"（token）已经自动存好了。

**❌ 有红色 = 某个账号密码不对。**
- 点开红色的那条，看返回里写的 `message`（中文）。
- 常见：`账号或密码错误` → 回第二步检查这个账号的密码。
- 改完密码后，**重新跑这个文件夹**。

---

### 3.2 再跑「01 变量准备」

同样方法：**鼠标移到文件夹名 → ▶ 运行 → 运行**。

它会把你的**学院、专业、课程、学生**的编号自动填好，后面靠它找对地方。

**✅ 全绿** → 继续。
**❌ 红** → 看 `message`。多半是账号没权限，回第二步检查管理员密码。

---

### 3.3 再跑「02 测试数据准备」

同样：**▶ 运行 → 运行**。

它会在系统里**新建**一个专门用于测试的学院、专业、课程（名字都带 `APITEST`）。这样后面的"删除/修改"操作只动这些假数据，不会碰真实数据。

**✅ 全绿** → 继续。

> 这一步新建的数据**不用管**，测完可以留着，不影响系统使用。

#### ✅ 跑完 3 步后，请自检一次（很重要）

在 Apifox 右侧「**变量 / Console**」里确认下面这些**都有值**（不是空的）：

| 变量 | 应该有值 | 没有值的后果 |
|---|---|---|
| `adminToken` | `eyJ...` 开头的长串 | 所有管理员请求都 401 |
| `teacherToken` `mentorToken` `leaderToken` `studentToken` | 同上 | 对应角色请求 401 |
| `deptId` | 一串数字 | 学院相关请求失败 |
| `courseId` | 一串字母数字 | 课程/排课/权重相关请求失败 |
| `testDeptId` `testCourseId` | 一串数字/字母 | 「99 危险操作」无法安全执行 |

> **如果某一项是空的**：回看它对应的那个请求，点「发送」单跑一次，看返回的 `message` 写了什么。
> 最常见原因是**账号密码不对**或**上游请求失败**。

---

### 3.4 正式测试（一组一组来）

现在可以逐组运行了，**按下面的顺序**：

| 顺序 | 文件夹 | 测什么 |
|---|---|---|
| 1 | `TC-AUTH 权限与鉴权` | 谁能干什么、不能干什么 |
| 2 | `TC-COM 通用流程` | 登录、改密码、个人信息 |
| 3 | `TC-ADM 管理员端` | 学院/专业/课程/学生/账号/排课 |
| 4 | `TC-TCH 教师端` | 课程标准、任务、打分 |
| 5 | `TC-STU 学生端` | 素质评价、分层测试 |
| 6 | `TC-E2E 端到端` | 跨模块 |
| 7 | `TC-BND 边界与异常` | 错误输入 |
| 8 | `TC-DIFF 已知差异` | **只看，不要判为 BUG**（见下面第四节） |

**每一组都是：鼠标移到文件夹 → ▶ → 运行。**

---

### 3.5 最后：「99 危险操作」——**不要直接点运行！**

这个文件夹里的请求会**真的删除数据**。

**正确做法：**
1. 点开文件夹，**一次只点一个请求**（不要点文件夹上的 ▶）。
2. 点开后，先看右边的「描述」，读完再决定。
3. 确认**只针对测试数据**后，再点那个请求的单条「发送」。

> 🚫 **绝对不要**在这个文件夹上点「运行」——会一次性把里面所有删除操作全执行。

## 第四步：怎么看结果

### 4.1 单个请求

点开任意一个请求 → 右侧点 **「发送」** → 下面会出现三块：

| 区域 | 看什么 |
|---|---|
| **Body（响应）** | 服务器返回的内容。中文 `message` 一般能看懂 |
| **Test Results（测试结果）** | **最重要**：绿色 ✅ = 通过，红色 ❌ = 失败 |
| **Status** | 状态码（如 200、403）。**不用懂**，看 Test Results 就行 |

### 4.2 批量运行

文件夹可见「运行」时右侧会打开运行面板，跑完会出现一份**测试报告**：

```
通过 34
失败 6
```

点失败的数字，能看到**哪一条失败、为什么失败**。

## 第五步：遇到"失败"怎么办（重要）

**失败不一定是 Bug！** 按这三类判断：

### 类型 A：账号/环境问题（最常见）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 所有请求都 `401` | token 没拿到 | 回第三步，重跑「00 登录」 |
| 请求连不上 / 超时 | 地址填错，或服务器没开 | 检查 `baseUrl` 是否填对、能否用浏览器打开 |
| `账号或密码错误` | 第二步密码填错 | 改密码后重跑「00 登录」 |

### 类型 B：环境版本旧（会大面积失败，不是你的错）

如果目标服务器**还没有部署最新代码**，下面这些用例会失败：

`TC-AUTH-002` `TC-AUTH-003` `TC-AUTH-004` `TC-AUTH-005` `TC-AUTH-013`
`TC-AUTH-032` `TC-AUTH-050` `TC-AUTH-052` `TC-COM-019` `TC-COM-020` `TC-ADM-017`

**表现**：本该被拒绝的请求，结果"成功了"。

**怎么办**：**不要当成 Bug**。这是服务器上跑的还是旧版本。找技术负责人确认是否已部署。

### 类型 C：真的要报告的 Bug

如果：
- 不是上面两类；
- 而且失败的请求**每次都能稳定复现**（多跑两次结果一样）；

那就记录下来，包含：
1. 用例编号（如 `TC-ADM-043`）
2. 返回的状态码
3. 返回里 `message` 的原文

## 第六节：`TC-DIFF` 组 —— **请务必看这里**

这个文件夹叫「已知差异」，意思是：**代码实际行为**和**《操作手册》写的**对不上。

比如：
- 手册说"忘记密码可以自己找回" → 实际**没有这个功能**
- 手册说"重复排课会显示冲突" → 实际**不检查冲突**
- 手册说"权重合计必须 100%" → 实际**不检查**

**这些请求的"预期结果"就是它的"当前实际结果"。**

> 🚫 **不要**把它判成 Bug。
> ✅ 它的作用是：**提醒你手册写错了**，需要决定"改手册"还是"改代码"。

## 第七节：需要你手动准备前置的 10 条用例

有些请求单独跑没意义，需要先准备条件。**这些在请求的「描述」里也写了**：

| 用例编号 | 运行前要先做什么 |
|---|---|
| `TC-AUTH-041` | 用同一个错误密码**连发 5 次**（运行面板里把"迭代次数"改成 5） |
| `TC-AUTH-042` | 先用管理员把某个账号**禁用**，再用它登录 |
| `TC-ADM-014/015/016` | 先在「02 测试数据准备」建好学院，拿到它的 id |
| `TC-ADM-063` | 先建一条**身份证相同**的账号，再建第二条 |
| `TC-COM-009` | 先把要重置密码的账号 id 填进变量 `targetUserId` |
| `TC-TCH-044/045` | 先调用「锁定任务」的接口，再调「修改任务」 |
| `TC-TCH-092` | 那个提交必须**已经打过一次分** |
| `TC-STU-086` | 需要 **5 个不同的学生账号**分别提交 |
| `TC-BND-002` | 需要一个**有学生的班级** |
| `TC-BND-008` | 运行面板里把"并发"设为 8 |

## 第八节：常见问题

**Q1：变量填了，但请求里还是显示 `{{teacherAccount}}`？**
A：① 检查右上角选中的环境是不是你填的那个；② 变量名有没有拼错（区分大小写）；③ 保存后刷新一下页面。

**Q2：`baseUrl` 要带 `/api` 吗？**
A：**不要**。只填到 `http://47.114.42.189`，后面的 `/api/xxx` 拼接在请求里。

**Q3：跑完「00 登录」后 token 自动存哪了？**
A：存进了变量。你不用管，看「Console（控制台）」会打印 `[写入变量] adminToken = eyJ...`。

**Q4：能只测某一个角色吗？**
A：能。但**必须先跑该角色的登录**（比如只测教师，就先单独跑「00 登录」里的「登录 · 教师」）。否则没有通行证。

**Q5：测完要清理我创建的数据吗？**
A：可选。用管理员账号在系统里搜 `APITEST`，手动删掉即可。**不清理也不影响使用。**

**Q6：`P0`、`P1`、`P2` 是什么意思？**
A：优先级。`P0` 最重要（不通过就别发布），`P2` 最次要。编号在每条请求名字的开头。

**Q7：结果里说"已知差异"，我要改代码吗？**
A：不用。先记录下来，找负责人决定是**改手册**还是**改代码**。
