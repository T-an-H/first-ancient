# 账号入库制重构 · 完整方案流程

> 版本：v1.0 ｜ 日期：2026-09-10 ｜ 适用范围：课程管理平台（course_platform）

---

## 第一段 · 改前 vs 改后 总览

| 维度 | 改前（现状） | 改后（目标） |
|---|---|---|
| **账号来源** | 两套并存：users 表靠脚本灌 + students 表开放注册 | 单一来源：**管理员唯一入库入口**，先入库后建号 |
| **谁能进系统** | 校外人员可自建学号注册、前端 mock 兜底可绕过登录 | **只有管理员添加入库的人**才能登录 |
| **入库必填** | 无统一规则（学号/姓名，可随意） | **姓名 + 电话 + 身份证**（身份证唯一、电话唯一），其他选填 |
| **学号/工号** | 手动指定（如 S2024001），无规则 | **系统自动生成**：当前年份 + 入库序号（学生/教师分开序列） |
| **登录方式** | 账号密码（账号=随意指定） | **手机号 或 学号/工号** 任选其一 + 密码 |
| **初始密码** | 全员统一 666666，永久可用 | **身份证后六位**（X 大写、保留前导 0），**首登强制改密** |
| **首登体验** | 直接进系统 | 先展示自己的学号/工号，再强制改密，改完才进系统 |
| **教师新增学生** | 手输姓名/Excel 导入即可凭空造人（不入库） | **只能从总库选择**，不在库提示联系管理员，后端二次校验 |
| **学院/班级** | 添加时就要填 | **可后分配**：入库时留空进"待分配池"，之后批量分配 |
| **批量能力** | 仅选课/排课有导入 | **入库支持 Excel 批量导入**（含校验报告），**数据可导出**（身份证脱敏） |
| **写接口权限** | 鉴权中间件写了但从未挂载，匿名可调 | **全部写接口必须 JWT**，账号管理接口仅 admin |
| **账号生命周期** | 无（只能删） | 启用/禁用（inactive 冻结），**冻结不删除**，数据可追溯 |
| **密码安全** | 无强制改密、无防爆破、密钥硬编码 | 强制改密 + 5 次失败锁 15 分钟 + JWT 密钥移入环境变量 |
| **操作留痕** | 无 | 账号增删改、重置密码全部审计记录 |

**一句话总结**：从"开放注册 + 双轨数据 + 无鉴权"的演示系统，改为"**管理员唯一入库 + 登录只认库 + 教师只从库选 + 全链路鉴权**"的正规学校式账号体系。

## 一、目标模型

```
管理员（唯一入库入口）
   │  添加学生 / 教师 / Excel 批量导入
   ▼
人员总库（students / teachers）          ← 档案先行，学院班级可后分配
   │  入库自动建号
   ▼
users 账号表（account=手机号，user_no=学号/工号）
   │  登录只认此表（status=active 才放行）
   ▼
统一登录（手机号 / 学号 / 工号 + 密码）
   │  首登：显示学号/工号 → 强制改密
   ▼
角色工作区（admin / teacher / mentor / leader / student）
```

## 二、现状问题清单（已核实）

### 致命问题（3 个，直接导致校外人员能进来）
1. **写接口零鉴权**——`server/index.js` 定义了 `authMiddleware` 但从未挂载，所有 POST/PUT/DELETE 匿名可调
2. **开放注册**——`/api/auth/register` 任何人可自建学号写入 students 表
3. **前端 mock 兜底**——`Login.vue` 内置 MOCK_USERS + demoMode，后端异常时绕过数据库登录

### 严重问题（4 个，导致"入库制"无法实现）
4. **管理员无添加入口**——加人只能改代码跑 `seed-users.js` 脚本
5. **教师可凭空建学生**——课程详情手输姓名、Excel 导入两条路，学生只存 localStorage 但选课同步 MySQL → 幽灵数据
6. **双账号体系**——users 表 + students 表并存，登录两条路径
7. **数据双轨**——MySQL 与 localStorage 各记一半，两端数据对不上

### 一般问题（4 个）
8. 密码全员 666666、无强制改密、无重置入口、无防爆破
9. JWT 密钥硬编码源码（`course-platform-secret-key-2026`）
10. 权限粒度粗（领导/导师与教师同权）
11. 无操作审计

## 三、核心流程设计

### 3.1 入库流程（管理员唯一入口）

```
[单个添加] 姓名 + 电话 + 身份证（必填）；学院/班级/角色/邮箱（选填）
[批量导入] Excel：姓名 | 电话 | 身份证 | 学院(选填) | 班级(选填) | 角色(教师必填)
      │
      ▼
三重校验：① 身份证唯一（查重，相同拒绝入库）
          ② 电话唯一（作为登录账号，必须唯一）
          ③ 身份证 18 位格式、电话 11 位格式
      │
      ▼ 全部通过
自动生成：
  学号/工号 = 当前年份(4位) + 入库序号(5位)     学生：202600001、202600002…
                                              教师：2026T00001、2026T00002…
  登录账号 = 手机号
  初始密码 = 身份证后 6 位（末位 X 转大写，保留前导 0）
  角色    = 学生→student；教师→teacher + sub_role(teacher/mentor/leader)
      │
      ▼
写入总库（students/teachers）+ 写入 users 表 → 入库完成，账号即刻可用
```

### 3.2 登录与改密流程

```
[输入] 手机号 或 学号/工号（一个输入框，前端不判断）
   │
   ▼
后端一条 SQL：WHERE account = ? OR user_no = ?
   │  （手机号、学号/工号各自唯一索引，不会匹配错人）
   ▼
密码校验（bcrypt）→ 5 次失败锁 15 分钟
   │
   ▼ 首次登录（need_change_password=1）
[改密引导页] 展示"你的学号/工号是 202600001，请牢记"
   → 输入新密码（≥8 位，含字母数字）→ 强制修改 → 才可进入系统
   │
   ▼ 非首次
直接进入角色工作区
```

### 3.3 教师新增学生流程（只能从总库选）

```
教师点击"新增学生"
   │
   ▼
弹窗改为选人：搜索 students 总库（学号/姓名/班级/电话）
   │
   ├── 命中总库 → 勾选 → 加入本课程（写 enrollments）
   │
   └── 未命中 → 拦截提示"该学生不在系统总库，请联系管理员添加入库"
              （可选：发起入库申请单 → 管理员审批）

后端兜底校验：所有选课接口校验 student_id 必须存在于 students 总库，否则拒绝。
Excel 导入选课：先核对总库，只加入库中已有的学生，未入库名单单独列出提示。
```

### 3.4 学院/班级后分配流程

```
入库时学院/班级留空 → 进入"待分配池"（department IS NULL 筛选）
   │
   ▼
管理页新增视图：筛选"未分配学院 / 未分配班级"
   │
   ▼
勾选多人 → 指定学院 → 指定该学院下班级 → 一键批量分配
   │
   ▼
已分配 → 归入学院/班级视图，随时可改（转班/调岗）
```

### 3.5 账号生命周期流程

```
入职/入学 → 管理员入库建号（active）→ 正常使用
   → 转班/调岗：只改档案（学院/班级/角色），账号不变、数据不动
   → 毕业/离职：改为 inactive（冻结）→ 冻结后不可登录，数据保留可追溯
   → 换手机号：管理员更新档案电话 → account 变，学号/工号不变，历史数据不受影响
   → 忘记密码：管理员重置 → 恢复为身份证后 6 位，下次登录强制改密
```

## 四、数据库改造（course_platform）

```sql
-- users 表新增字段
ALTER TABLE users
  ADD COLUMN user_no       VARCHAR(32)  UNIQUE COMMENT '学号/工号（业务身份）',
  ADD COLUMN id_card       VARCHAR(255) DEFAULT '' COMMENT '身份证（加密存储）',
  ADD COLUMN ref_type      VARCHAR(16)  DEFAULT '' COMMENT 'student/teacher',
  ADD COLUMN ref_id        VARCHAR(64)  DEFAULT '' COMMENT '关联总库人员ID',
  ADD COLUMN need_change_password TINYINT(1) DEFAULT 1 COMMENT '首登强制改密',
  ADD COLUMN fail_count    INT          DEFAULT 0 COMMENT '连续失败次数',
  ADD COLUMN lock_until    DATETIME     DEFAULT NULL COMMENT '锁定截止时间',
  ADD COLUMN last_login_at DATETIME     DEFAULT NULL COMMENT '最近登录时间';

-- 唯一索引保障
ALTER TABLE users ADD UNIQUE KEY uk_account (account);   -- 手机号唯一
ALTER TABLE users ADD UNIQUE KEY uk_user_no (user_no);   -- 学号/工号唯一

-- students 表：password 字段废弃不再写入（登录只走 users 表）
-- teachers 表：保留档案字段，通过 users.ref_id 关联账号
```

**说明**：`account` 存手机号（登录主凭据），`user_no` 存学号/工号（业务身份，选课/成绩/分组都认它），两者分离、各自唯一。

## 七、安全机制

1. **全链路鉴权**：写接口必须 JWT；账号管理仅 admin
2. **JWT 密钥环境变量化**（不再硬编码）
3. **初始密码策略**：身份证后 6 位（X 大写、保留前导 0），首登强制改密（≥8 位含字母数字）
4. **防爆破**：单账号 5 次失败锁定 15 分钟（fail_count / lock_until）
5. **身份证保护**：数据库加密存储；页面与导出脱敏显示（110\*\*\*\*\*\*\*\*\*\*\*1234）；导出身份证列默认脱敏
6. **审计日志**：账号增删改、重置密码、分配学院班级，记录操作人 + 时间（新增 account_logs 表）

## 八、存量数据迁移（上线时执行一次）

1. 现有 41 个 users 账号保留，逐条补 `user_no`（学号/工号）、`ref_type`、`ref_id` 关联
2. 前端 mock 的几十个学生名单，决策后一次性沉淀进 students 总库（或由管理员重新录入）
3. 历史选课/成绩关联的是旧学号（S2024001 等）——保留旧学号作为别名，或一次性重映射到新学号
4. 清理幽灵选课：enrollments 中 student_id 不在总库的记录，核对后删除或补录档案
5. localStorage 中的 mock 数据不再作为数据源，前端所有业务数据逐步迁移到 API
