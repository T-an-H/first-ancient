## 0. 使用说明

### 0.1 环境准备（所有用例的前置）

```bash
# 1) 启动后端（默认端口 3000）
cd server && npm install && npm start

# 2) 启动前端（默认请求 3002，需对齐其一）
cd .. && npm install && VITE_API_PORT=3000 npm run dev
```

> ⚠️ **后端 3000、前端默认找 3002**——不对齐的话界面会一片空白且控制台报网络错误。
> 详见 `docs/接口文档.md` §1.1。

打开浏览器访问终端里提示的地址（通常 `http://localhost:5173`）。

### 0.2 通用导航地图（后面大量步骤会引用）

**页面右上角 / 左侧边栏是主要入口。登录后按角色看到不同菜单：**

| 角色 | 左侧菜单（按顺序） |
|---|---|
| 管理员 | 「课程管理」「学生管理」「教师管理」「账号管理」「个人中心」 |
| 教师 | 「我的课程」「课程表」「待办」「个人中心」 |
| 企业导师 | 「我的课程」「课程表」「待办」「个人中心」 |
| 学院领导 | 「课程总览」「学员总览」「个人中心」 |
| 学生 | 「个人中心」「我的课表」「我的课程」「成绩查询」「待办」 |

**教师/导师端进入某门课后的「课程详情」页，顶部有这些 Tab**（按顺序）：
「学生管理」「课程任务与评价」「**素质评价**」「**权重分配**」「成绩管理」「综合评价」

> ⚠️ 注意顺序：**「素质评价」在「权重分配」之前**（不是之后）。
> 「上传课程标准」「新增任务」这两个按钮在「课程任务与评价」Tab 内的**知识图谱组件**里
>（页面中的「知识图谱 / 任务地图」区域），不在 Tab 栏上。

**学生端进入某门课后的「课程学习」页，顶部有这些 Tab**（按顺序）：
「AI分层」「课程图谱」「课程标准」「素质评价」「综合评价」

> ⚠️ **注意两级结构**：学生端的「**工单**」「**评教**」**不是课程级 Tab**，
> 它们在「课程图谱」里**点进某个任务后的任务详情**内。
> 进入路径：`我的课程` → 点课程 → `课程图谱` → 在「任务列表」里点任务名 → 任务详情内出现
> 「预习资料」「测试」「本节课资料」「工单」「评教」五个 Tab。

> ⚠️ 管理员端侧边栏里上下相邻的「教学管理」「企业导师管理」「学院管理」等是**分组分隔标题**，**不是可点击的菜单项**。

### 0.3 判读约定

- **预期**写的是"界面上应该看到什么"。
- 提到"接口返回码"的地方，请按 `F12` 打开开发者工具 → `Network` 面板查看。
- 标 ⚠️ 的用例是**已知差异**，期望值以 `docs/接口文档.md` §4 为准，**不要按操作手册判为缺陷**。

## 1. 通用流程（TC-COM）

### 1.1 登录、小智、待办

#### TC-COM-003 登录页角色标签不可点 ｜ P2 ｜ UI

**前置**：已启动前端，未登录。

**操作步骤**：
1. 浏览器打开前端地址，停在登录页。
2. 观察页面顶部/中部，找到「管理员」「教师」「学生」这三个标签。
3. 用鼠标**逐个点击**这三个标签。
4. 再次点击，观察页面是否有任何变化。

**预期结果**：
- 三个标签**只是展示**（说明平台支持哪些角色），**点击没有任何反应**——不跳转、不切换、不报错。
- 登录后由系统按账号**自动判定**角色，不需要手动选。

**来源**：操作手册 §一·一 提示。

#### TC-COM-008 ⚠️ 忘记密码无自助找回 ｜ P1 ｜ UI

> **【已知差异】** 后端**没有**任何找回密码接口。本用例是**确认现状**，不是验证功能。

**前置**：停在登录页。

**操作步骤**：
1. 在登录页找到「忘记密码？」链接。
2. 点击它，观察页面反应。
3. 若弹出输入框，尝试填入手机号并提交。

**预期结果（当前实现）**：
- 后端**不存在**找回密码接口（`docs/接口文档.md` §4 已记录）。
- 该入口若有交互，**只能是前端假动作**，不会真的重置密码。
- **真正的恢复途径**：联系管理员，在「账号管理」页执行「重置密码」（见 TC-COM-009）。

**处理建议**：改手册删掉该条，或后端补一个找回接口。

#### TC-COM-013 切换账号保留多账号 ｜ P1 ｜ UI

**前置**：已准备好 **5 个不同角色**的账号（管理员 / 教师 / 学生 / 企业导师 / 学院领导）及其密码。

**操作步骤**：
1. 用**第 1 个账号**（如管理员）登录。
2. 点击左侧菜单最下方的「个人中心」。
3. 在个人中心页找到「切换账号」按钮并点击。
4. 在弹出的账号列表中，若有「添加账号 / 登录其他账号」入口，点击它。
5. 输入**第 2 个账号**（教师）的账号与密码，登录。
6. 重复步骤 2–4，依次登录第 3、4、5 个账号。
7. 此时切回「切换账号」列表，观察列表里保留了几个账号。
8. 从列表中**直接点选第 1 个账号**（管理员），观察是否**无需重新输密码**即可进入。

**预期结果**：
- 账号列表**最多保留 5 个**账号。
- 点选列表中的账号可**快速切回**，不需要重新输入密码。
- 切换过去后，原账号的数据（如未提交的表单）仍然保留，不丢失。

**来源**：操作手册 §一·四、FAQ Q24。

#### TC-COM-015 小智按角色给快捷操作 ｜ P2 ｜ UI

**前置**：分别准备学生 / 教师 / 管理员三类账号。

**操作步骤**：
1. 用**学生**账号登录，进入工作区。
2. 找到页面**右下角**的圆形悬浮按钮，鼠标移上去会显示「打开小智」，点击它。
3. 展开对话面板后，观察面板底部的**快捷操作按钮**有哪些，记下来。
4. 关闭面板，退出登录。
5. 换成**教师**账号登录，重复步骤 2–3，记录快捷按钮。
6. 换成**管理员**账号登录，重复步骤 2–3，记录快捷按钮。

**预期结果**：快捷按钮**按角色不同**：

| 角色 | 应看到的快捷按钮 |
|---|---|
| 学生 | 看成绩 / 看课表 / 看进度 / 我的课程 |
| 教师 | 我的课程 / 课程表 / 评价管理 / 学生进度 |
| 管理员 | 切换学院 / 课程管理 / 班级管理 / 学生详情 |
| 企业导师 / 学院领导 | 平台功能 / 我的权限 / 怎么用小智 |

**来源**：操作手册 §一·五。

#### TC-COM-016 小智导航跳转 ｜ P1 ｜ UI

**前置**：以学生身份登录。

**操作步骤**：
1. 点击右下角圆形悬浮按钮打开小智面板。
2. 在面板**最下方**的输入框里输入：`帮我看成绩`。
3. 按回车或点发送。
4. 等待回复（通常 1–3 秒）。
5. 观察页面是否发生跳转。
6. 阅读回复内容下方的「思路摘要」，以及末尾的来源标记。

**预期结果**：
- 目标唯一时，小智回复类似「好，我现在带你过去」，页面**自动跳转到成绩查询页**。
- 每条回复下方有「思路摘要」。
- 末尾标注来源：**「LLM 决策」**（后端大模型判断）或 **「本地兜底」**（大模型不可用，前端规则判断）。
- **两种情况都能正常跳转**，不影响使用。

**来源**：操作手册 §一·五。

#### TC-COM-017 小智追问确认 ｜ P2 ｜ UI

**前置**：以教师身份登录（教师能跳转的目标较多，容易触发追问）。

**操作步骤**：
1. 打开小智面板。
2. 输入一个**目标不唯一**的指令，例如：`打开评价`（教师端既可能指"评价管理"，也可能指某门课下的"评价"）。
3. 发送，等待回复。
4. 观察小智是否列出**若干个候选按钮**。
5. 点击其中一个候选按钮。

**预期结果**：
- 小智**不直接跳转**，而是列出若干候选按钮（如"评价管理""XX课程的评价"）。
- 点击其中任意一个，页面跳转到对应位置。

**来源**：操作手册 §一·五。

#### TC-COM-018 小智只导航不改数据 ｜ P1 ｜ UI

**前置**：以学生身份登录，且该生**有未提交的作业**（便于观察是否被"代提交"）。

**操作步骤**：
1. 打开小智面板。
2. 输入：`帮我提交作业`，发送。
3. 观察回复，以及页面是否自动帮你提交了作业。
4. 再输入：`帮我改成绩`，发送。
5. 观察回复，以及成绩是否发生变化。

**预期结果**：
- 小智**只负责"带你去页面"**，或给出文字说明，**不会替你提交数据、改成绩或执行删除**。
- 作业的提交状态**没有变化**，成绩**没有变化**。
- 需要实际填写与提交时，仍要你本人在页面上操作。

**来源**：操作手册 §一·五 提示。

#### TC-COM-010 个人信息读取 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以学生身份登录。

**操作步骤**：
1. 点击左侧菜单的「个人中心」。
2. 查看页面上显示的字段。
3. 按 `F12` 打开开发者工具 → `Network` 面板 → 刷新页面 → 找到 `profile` 请求 → 查看返回的 JSON。

**预期结果**：
- 界面显示的姓名 / 学号 / 手机号 / 身份 / 学院，与接口返回的 `profile` 字段**一致**。
- 接口返回字段包含：`name`、`userNo`、`phone`、`department`、`role`、`subRole`、`roleLabel`、`className`。

#### TC-COM-019 待办跨设备保留 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以学生身份登录。

**操作步骤**：
1. 点击左侧菜单的「待办」。
2. 找到任意一条待办，点击它左侧的圆圈/勾选框，把它**标记为已完成**。
3. 再找到另一条待办，鼠标移上去，点击右侧出现的**删除**图标，把它删掉。
4. 按 `F12` → `Application`（Chrome）或 `Storage`（Firefox）→ 展开 `Session Storage` → 删除里面所有条目（模拟"换了一台设备"）。
5. **不要关浏览器**，直接刷新页面（`F5`）。
6. 用**同一个学生账号**重新登录。
7. 再次点击左侧「待办」。

**预期结果**：
- 步骤 2 标记为已完成的那条待办，**仍然是已完成状态**。
- 步骤 3 删掉的那条，**没有复活**。
- 说明待办状态已落库，不再只依赖浏览器本地存储。

**来源**：`docs/接口文档.md` §2.7。

## 2. 管理员端（TC-ADM）

### 2.1 学院

#### TC-ADM-013 查看删除影响面 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录，且已存在至少一个**下面有数据**的学院。

**操作步骤**：
1. 登录后进入「选择管理学院」页。
2. 把鼠标移到**有数据的那个学院卡片**上。
3. 找到并点击该卡片上的「删除」图标/按钮（通常在卡片右上角或悬停时出现）。
4. 观察弹出的确认框内容——**先不要确认**。

**预期结果**：
- 弹出确认框，其中**列出了该学院下的关联数据数量**（专业数、课程数、班级数、学生数、教师数，以及排课/选课/评价/成绩等条数）。
- 界面用这些数字告诉管理员"删掉会损失什么"，而不是直接删。
- 此时点「取消」，学院**不应被删除**。

**来源**：`docs/接口文档.md` §2.3；操作手册 §二·二。

#### TC-ADM-023 删除专业 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录，已选定某个学院。

**操作步骤**：
1. 点击左侧菜单「课程管理」。
2. 页面顶部会显示「当前学院：XX学院」，下方是专业卡片列表。
3. 找到要删的专业卡片。
4. 把鼠标移到该卡片上，点击出现的「删除」按钮。
5. 在确认框里点「确定」。

**预期结果**：
- 弹出删除确认，确认后该专业从列表中**消失**。
- 刷新页面后，该专业**仍然不在**（确认真删了，不是只从界面上隐藏）。

**来源**：操作手册 §二·三。

### 2.2 教师

#### TC-ADM-031 批量添加教师 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录；已准备一份填好的教师 Excel（列含 姓名 / 手机号 / 身份证号 / 学院 / 身份）。

**操作步骤**：
1. 点击左侧菜单「教师管理」。
2. 在页面右上角找到「模板下载」按钮，点击下载标准模板。
3. 打开模板，按列填写若干教师（**身份证号必须是 18 位，手机号 11 位**），保存为 `.xlsx`。
4. 回到「教师管理」页，点击「批量添加」按钮。
5. 在文件选择框里选中刚才填好的 Excel，确认上传。
6. 等待处理完成，阅读弹出的「导入结果」。

**预期结果**：
- 弹出导入结果，显示**成功入库 N 条**。
- 若有失败行，结果里会**逐行列出失败原因**（如"身份证已入库"），不会整批失败。
- 导入的记录出现在教师列表中。

**来源**：操作手册 §二·四。

#### TC-ADM-032 教师列表搜索与筛选 ｜ P2 ｜ UI

**前置**：以管理员登录；教师列表里有多位不同学院、不同姓名的教师。

**操作步骤**：
1. 点击左侧菜单「教师管理」。
2. 在页面上方的**搜索框**（提示文字「搜索教师姓名、邮箱、电话或学院」）里输入某位教师的姓名的**一部分**（如只输姓氏），观察列表是否实时过滤。
3. 清空搜索框，改输入一个**邮箱片段**，观察过滤结果。
4. 清空搜索框，改输入**电话号码片段**，观察过滤结果。
5. 清空搜索框，改用搜索框右侧的「全部学院」下拉框，选中某个学院。

**预期结果**：
- 姓名、邮箱、电话三种关键字**都能过滤**，列表实时收敛到匹配项。
- 学院下拉筛选生效，只显示该学院的教师。
- 无匹配时列表显示空态，不报错。

**来源**：操作手册 §二·四。

#### TC-ADM-033 编辑教师 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录，教师列表中有数据。

**操作步骤**：
1. 点击左侧菜单「教师管理」。
2. 找到目标教师所在行，把鼠标移到该行上。
3. 行尾会出现两个图标按钮，点击左边的「编辑教师」。
4. 在弹出的表单里修改姓名（例如在原名后加「-改名」）和手机号。
5. 点击「保存」。

**预期结果**：
- 弹窗关闭，提示保存成功。
- 列表中该教师的姓名/手机号**立即更新**。
- 刷新页面后仍是新值。

**来源**：操作手册 §二·四。

#### TC-ADM-034 删除教师 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录；准备一个**没有关联授课**的教师作为删除对象。

**操作步骤**：
1. 点击左侧菜单「教师管理」。
2. 把鼠标移到目标教师所在行，点击行尾的「删除教师」图标。
3. 在确认框里点「确定」。

**预期结果**：
- 若该教师**没有关联课程**：删除成功，从列表消失。
- 若该教师**有授课关联**：操作被拒绝，并给出可读提示（受保护机制），教师**仍然在列表中**。

**来源**：操作手册 §二·四。

### 2.3 课程

#### TC-ADM-070 分配学院/班级 ｜ P1 ｜ 接口+UI（UI 部分）

**前置**：以管理员登录；账号列表里有学生账号。

**操作步骤**：
1. 点击左侧菜单「账号管理」。
2. 用搜索框（提示「搜索姓名 / 学号 / 手机号」）找到目标学生账号。
3. 点击该行右侧的**分配**入口（若按钮文案为「分配学院 / 分配班级」，照点即可）。
4. 在弹窗里选择目标「学院」与「班级」。
5. 点「保存」/「确定」。
6. 回到「学生管理」页，找到该学生，查看他的学院与班级是否变了。

**预期结果**：
- 提示分配成功。
- 学生端登录后，个人中心的学院/班级显示为**新值**。

#### TC-DIFF-002 忘记密码无自助找回 ｜ P1 ｜ UI

#### TC-DIFF-003 排课无冲突检测 ｜ P2 ｜ UI
**操作步骤**：
1. 以管理员登录 → 「课程管理」→ 进入某课程 → 进入其排课记录页。
2. 点击「新增排课」，用**与已有排课完全相同的教室、星期、时间段**再录一条。

**【已知差异】** 后端**没有冲突检测**。手册 §二·九 说的"冲突"标记**当前无实现**（前端可能部分实现，需实测确认）。
**处理建议**：确认前端是否实现；都没有则删手册该条。

#### TC-DIFF-005 任务锁定与截止时间未进手册 ｜ P1 ｜ UI
**操作步骤**：
1. 以教师登录 → 进某课程 → 「课程任务与评价」Tab → 找到任务列表。
2. 查看任务上是否有「锁定」/「设置截止时间」这类入口。
3. 若有，尝试锁定一个任务，然后尝试修改它。

**【已知差异】** 代码里**有完整实现**（锁定后禁止修改、截止时间与锁定互斥），但**操作手册只字未提**。
**处理建议**：**补手册**（这是手册漏写，不是代码问题）。

#### TC-DIFF-006 问卷编辑入口未进手册 ｜ P2 ｜ UI
**操作步骤**：
1. 以教师登录 → 进某课程 → 找找有没有"问卷 / 评教指标"的编辑入口。
2. 查看「评教」Tab 是否提供编辑 10 道评教题的入口。

**【已知差异】** `questionnaire` 接口齐全（增删改查都有），但**手册未描述在哪里配置问卷**。
**处理建议**：确认前端是否真有入口；没有的话这 10 道题就是初始化数据。

#### TC-DIFF-013 素质成果文件上限 2MB vs 720KB ｜ P1 ｜ UI
**前置**：准备一个 **1MB** 的文件（介于 720KB 与手册说的 2MB 之间）。

**操作步骤**：
1. 以学生登录 → 「我的课程」→ 进某课程 → 点「素质评价」Tab。

**【已知差异】** 实际上限是 **720KB**（不是手册 §四·六 写的 2MB）。

**处理建议**：改手册为 720KB；或由运维放开 nginx 后同步调大三处（前端基准 / Express / nginx）。
