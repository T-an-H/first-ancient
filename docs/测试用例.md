# 课程多元评价平台 · 测试用例

> ## 本文档的用途与用法
>
> 由 **`docs/接口文档.md`（接口事实）** + **《课程多元评价平台操作手册》（界面流程）** 交叉生成。
>
> ### 覆盖层级（本文档同时覆盖两层）
>
> | 类型 | 含义 | 执行方式 |
> |---|---|---|
> | **接口** | 直接对 HTTP 接口断言 | 可自动化：`curl` / Node 脚本 / Postman。**可回归、可进 CI** |
> | **UI** | 界面上操作并观察结果 | 需 `npm run dev`；手工执行，或后续用 Playwright 固化 |
> | **接口+UI** | 同一功能两层都要验 | 先接口后 UI，UI 用于确认前端接线正确 |
>
> ### 用例编号
>
> `TC-<模块>-<序号>`，模块：`AUTH` 鉴权权限 / `COM` 通用 / `ADM` 管理员 / `TCH` 教师 / `STU` 学生 / `MEN` 企业导师 / `E2E` 端到端 / `DIFF` 手册差异 / `BND` 边界异常
>
> ### 优先级
>
> `P0` 阻断级（不通过则不可发布） · `P1` 重要 · `P2` 次要
>
> ### 来源标注
>
> `接口§x.y` 指向本文档配套的接口文档章节；`手册§x` 指向操作手册章节。

## 0. 测试环境与准备（非用例）

### 0.1 环境对齐 ⚠️ 不先做这步，接口用例会全红

| 项 | 值 |
|---|---|
| 后端启动 | `cd server && npm install && PORT=3002 npm start`（或让前端指向 3000） |
| 前端启动 | `npm install && VITE_API_PORT=3000 npm run dev` |
| 默认端口 | 后端 **3000**、前端请求 **3002** —— 必须对齐其一 |
| 数据库 | 需可连的 MySQL（`server/db.js`）。**先跑一次后端**，确认启动日志里建表成功 |

**冒烟前置**：`GET /api/health` 返回 `{"status":"ok"}`。

### 0.2 测试账号矩阵

| 角色 | 账号 | 说明 |
|---|---|---|
| 管理员 | `admin` | 口令由环境决定 |
| 教师 | 工号形如 `2026T00026` | 初始密码=身份证后 6 位 |
| 学生 | 学号形如 `202600034` | 同上 |
| 企业导师 | 工号，`sub_role=mentor` | 同上 |
| 学院领导 | 工号，`sub_role=leader` | 同上，另需一个 `role='leader'` 的纯领导 |

> ⚠️ **初始密码不是 `666666` 这类固定值**（见 §DIFF-001）。测试账号若已改过密，先由管理员重置。

### 0.3 数据准备

需要用到的数据（缺失则相关用例无法执行）：

- 1 个学院、1 个专业（分类）、1 门课程（含授课教师 + 企业导师）
- 1 个班级 + ≥3 名学生选课，且已完成分组
- 1 门课程配好评价模板与成绩权重
- 1 个课程任务（项目），含预习资料/工单文件
- 1 份课程标准文件（用于上传/下载用例）

### 0.4 判读约定

- 接口用例的「预期」写成 **HTTP状态码 + 关键字段**，便于自动化断言。
- UI 用例的「预期」写成 **界面上可见的结果**（含应出现的提示文案）。
- 标 ⚠️ 的用例：**当前实现与手册不一致**，期望值以接口文档 §4 为准，不是"应该修好"。

## 1. 权限与鉴权（本次改造重点）

> 本模块几乎全是**接口层**用例，是回归测试的核心，建议全部自动化。
> 背景：此前除账号管理外，所有写接口只验"登录"不验"角色"。现已收紧。

### 1.1 管理类写接口 — 仅管理员

> 涉及资源：`departments` / `classes` / `students` / `teachers` / `categories` / `courses`
> 涉及方法：POST（新建）、PUT /:id（修改）、DELETE /:id（删除），以及 `categories` 额外的 `POST /sync`

#### TC-AUTH-001 管理员可写全部管理类资源 ｜ P0 ｜ 接口
- **前置**：管理员 token
- **步骤**：依次调用
  `POST /api/departments`、`PUT /api/departments/:id`、`DELETE /api/departments/:id`、
  `POST /api/classes`、`PUT /api/classes/:id`、`DELETE /api/classes/:id`、
  `POST /api/students`、`PUT /api/students/:id`、`DELETE /api/students/:id`、
  `PUT /api/teachers/:id`、`DELETE /api/teachers/:id`、
  `POST /api/categories`、`PUT /api/categories/:id`、`DELETE /api/categories/:id`、`POST /api/categories/sync`、
  `POST /api/courses`、`PUT /api/courses/:id`、`DELETE /api/courses/:id`
- **预期**：**全部不返回 401/403**（返回 200/201/400/404 等业务码均可）
- **来源**：接口§1.2、§2.3

#### TC-AUTH-002 学生写管理类资源一律 403 ｜ P0 ｜ 接口
- **前置**：学生 token
- **步骤**：同 TC-AUTH-001 的 18 条写路由
- **预期**：**每条均返回 403**，body `{success:false, message:"无权限执行该操作"}`
- **来源**：接口§1.2

#### TC-AUTH-003 教师写管理类资源一律 403 ｜ P0 ｜ 接口
- **前置**：教师 token
- **步骤**：同 TC-AUTH-001
- **预期**：**每条均返回 403**
- **说明**：课程/学生/学院/专业/教师/班级 这些**不是**教师可改的资源
- **来源**：接口§1.2

#### TC-AUTH-004 企业导师写管理类资源一律 403 ｜ P1 ｜ 接口
- **前置**：`sub_role=mentor` 的 token
- **预期**：18 条写路由全部 403

#### TC-AUTH-005 学院领导写管理类资源一律 403 ｜ P1 ｜ 接口
- **前置**：`sub_role=leader` 的 token
- **预期**：18 条写路由全部 403

#### TC-AUTH-006 未登录写管理类资源一律 401 ｜ P0 ｜ 接口
- **前置**：不带 `Authorization` 头
- **步骤**：同 TC-AUTH-001
- **预期**：**每条均返回 401**，`{success:false, message:"未登录或登录已过期"}`

### 1.2 排课写接口 — 放行教职工（例外）

> ⚠️ 这是**唯一**对教职工放行的管理类资源。原因：教师端"新建课程内班级"会自动补写一条排课。
> 涉及：`POST /api/schedules/bulk`、`PUT /api/schedules/:id`、`DELETE /api/schedules/:id`

#### TC-AUTH-010 教师可写排课 ｜ P0 ｜ 接口
- **前置**：教师 token
- **步骤**：`POST /api/schedules/bulk` body `{schedules:[一条合法排课]}`
- **预期**：**不返回 401/403**（应 200，`success:true`）
- **来源**：接口§2.3 排课

#### TC-AUTH-011 企业导师可写排课 ｜ P1 ｜ 接口
- **前置**：mentor token ｜ **预期**：不返回 401/403

#### TC-AUTH-012 学院领导可写排课 ｜ P1 ｜ 接口
- **前置**：leader token ｜ **预期**：不返回 401/403

#### TC-AUTH-013 学生写排课一律 403 ｜ P0 ｜ 接口
- **前置**：学生 token
- **步骤**：3 条排课写路由
- **预期**：**全部 403**

#### TC-AUTH-014 未登录写排课 401 ｜ P0 ｜ 接口
- **预期**：3 条全部 401

#### TC-AUTH-015 教师端"新建课程内班级"仍能写入排课 ｜ P0 ｜ 接口+UI
- **前置**：教师登录；进入某课程详情
- **步骤**：
  1. 【UI】"学生管理" → "新建班级" → 填班级名 + 勾选成员 → 确认
  2. 【接口】抓包观察 `POST /api/schedules/bulk` 的响应码
  3. 【UI】读最终弹出提示的内容
- **预期**：
  - 该请求**不是 403**；排课确实写入（可在课表或 `GET /api/schedules?courseId=` 中查到）
  - 弹窗**不含任何 ⚠️ 告警**
- **说明**：此处前端**已改为不静默**（原先裸 `catch {}` 会吞错）。
  若该请求被拦，弹窗会明确提示"该班级对应的排课记录未能写入（课表中不会出现这节课）"。
  **仍建议查响应码**——提示依赖前端逻辑，响应码不会骗人
- **来源**：接口§2.3、手册§三·四

#### TC-AUTH-016 建班级失败时必须给出告警 ｜ P0 ｜ UI
- **前置**：教师登录；**临时断开后端**（或让接口返回 403）
- **步骤**："学生管理" → "新建班级" → 填班级名 + 勾选成员 → 确认
- **预期**：弹窗**包含** ⚠️ 告警，明确说明哪些写入没成功（班级记录 / 排课 / 选课 / 班级归属），
  而不是只显示"已创建班级"的成功文案
- **说明**：这是本次修复的核心——**失败必须可见**。若此条不通过，说明静默吞错回归了
- **来源**：`src/pages/teacher/CourseDetail.vue` `saveAddClass()`

### 1.3 教学类接口 — 有意不校验角色

#### TC-AUTH-020 学生可调教学类写接口 ｜ P1 ｜ 接口
- **步骤**：学生 token 调 `POST /api/eval/save`、`POST /api/projects/:id/progress`、`POST /api/quality-evaluations/submit`
- **预期**：**不被 403 拦截**（这是设计如此，靠业务逻辑约束）
- **说明**：本条用于**确认设计边界**，避免误以为"应该收紧"

#### TC-AUTH-021 ⚠️ 企业导师可越权调教师写接口 ｜ P1 ｜ 接口
- **步骤**：mentor token 调 `POST /api/projects`（新建任务）
- **预期**：**当前不被拦截**（后端无角色校验）
- **说明**：手册§五说企业导师端"只读、无新增按钮"，但那是**前端隐藏**。接口层拦不住。**记录为已知差异**，不是"应该 403"
- **来源**：接口§4

### 1.4 读接口不得被误伤（回归）

#### TC-AUTH-030 未带 token 的 GET 仍 200 ｜ P0 ｜ 接口
- **步骤**：不带 token `GET /api/departments`、`/api/classes`、`/api/students`、`/api/teachers`、`/api/categories`、`/api/courses`、`/api/schedules`
- **预期**：**全部 200**
- **说明**：收紧写接口时最易犯的错是"整表挂守卫"，会让 GET 全部 401。**这条是防回归的关键**
- **来源**：接口§1.2

#### TC-AUTH-031 学生身份 GET 也 200 ｜ P1 ｜ 接口
- **预期**：同上 7 条，带学生 token 仍 200

#### TC-AUTH-032 需 token 的 GET 无 token 应 401 ｜ P1 ｜ 接口
- **步骤**：不带 token 调 `GET /api/user/profile`、`GET /api/auth/verify`、`GET /api/todos`
- **预期**：**全部 401**
- **说明**：这几个 GET 虽被全局放行，但在 handler 内自行解析 token
- **来源**：接口§1.2、§2.7

### 1.5 账号状态与凭证

#### TC-AUTH-040 密码错返回剩余次数 ｜ P0 ｜ 接口
- **步骤**：用正确账号 + 错误密码调 `POST /api/user/login`
- **预期**：401，message 含 `还剩 4 次机会`（首次错）

#### TC-AUTH-041 连错 5 次锁定 15 分钟 ｜ P0 ｜ 接口
- **步骤**：同一账号连续 5 次错误密码
- **预期**：第 5 次返回 **423**，`code:"ACCOUNT_LOCKED"`，message 含 `已锁定 15 分钟`
- **补充**：锁定期内**即使密码正确**也应返回 423

#### TC-AUTH-042 禁用账号无法登录 ｜ P1 ｜ 接口
- **前置**：管理员将某账号 `status=inactive`
- **预期**：登录返回 **403** `该账号已被禁用`

#### TC-AUTH-043 无效 token 401 ｜ P1 ｜ 接口
- **步骤**：`Authorization: Bearer 乱码` 调任一写接口
- **预期**：401 `登录凭证无效，请重新登录`

#### TC-AUTH-044 首登标记为真时必须改密 ｜ P0 ｜ 接口+UI
- **前置**：新入库账号（`need_change_password=1`）
- **步骤**：【接口】登录 → 【UI】观察是否被强制跳到改密页
- **预期**：登录响应 `need_change_password: true`；UI 不进入工作区，直接显示"首次登录 · 修改密码"
- **来源**：手册§一·二

### 1.6 小智接口限流

#### TC-AUTH-050 未登录调小智 401 ｜ P0 ｜ 接口
- **步骤**：不带 token `POST /api/assistant/navigate`
- **预期**：**401**（此前是公开接口，属本次修复项）
- **来源**：接口§2.8

#### TC-AUTH-051 登录后小智可用 ｜ P0 ｜ 接口
- **预期**：200，`success:true`

#### TC-AUTH-052 超过 20 次/分钟返回 429 ｜ P1 ｜ 接口
- **步骤**：同一用户 1 分钟内连续调用 21 次
- **预期**：**第 1–20 次 200，第 21 次 429**
- **说明**：限流按用户维度，换一个用户应重新计数

## 2. 通用流程

> 对应手册第一部分 + 接口文档 §2.1。

#### TC-COM-001 统一登录成功（手机号） ｜ P0 ｜ 接口+UI
- **步骤**：【接口】`POST /api/user/login {account:"138…", password:"…"}`；【UI】登录页输入手机号+密码点"登录"
- **预期**：200，返回 `token` / `user` / `portal`；UI 按 `portal` 跳转到对应工作区
- **来源**：手册§一·一、接口§2.1

#### TC-COM-002 统一登录成功（学号/工号） ｜ P0 ｜ 接口+UI
- **步骤**：`account` 传学号
- **预期**：同上。确认**手机号与学号都能登录**（后端 `WHERE account=? OR user_no=?`）

#### TC-COM-003 登录页角色标签不可点 ｜ P2 ｜ UI
- **步骤**：观察登录页顶部"管理员/教师/学生"标签
- **预期**：**仅展示，不响应点击**；角色由账号自动判定
- **来源**：手册§一·一 提示

#### TC-COM-004 首次登录强制改密 ｜ P0 ｜ UI
- **步骤**：用 `need_change_password=1` 的账号登录
- **预期**：跳"首次登录 · 修改密码"页，页面显示"你的学号/工号是 XXXX"
- **来源**：手册§一·二

#### TC-COM-005 新密码规则校验 ｜ P0 ｜ 接口+UI
- **步骤**：改密时依次提交：`1234567`（7位）、`abcdefgh`（无数字）、`12345678`（无字母）、`abc12345`（合规）
- **预期**：前三次 **400**（`新密码至少 8 位` / `新密码需同时包含字母和数字`）；第四次 200
- **来源**：接口§1.6

#### TC-COM-006 改密需验旧密码（日常改密场景） ｜ P1 ｜ 接口
- **步骤**：传 `oldPassword` 但值错误
- **预期**：400 `旧密码不正确`

#### TC-COM-007 首登改密可不传旧密码 ｜ P1 ｜ 接口
- **步骤**：只传 `newPassword`
- **预期**：200，且 `need_change_password` 被置 0

#### TC-COM-008 ⚠️ 忘记密码无自助找回 ｜ P1 ｜ UI
- **步骤**：登录页点"忘记密码？"
- **预期**：**后端无任何找回接口**。该入口若存在只能是前端假动作；实际恢复途径是**管理员重置**
- **说明**：**不要**按手册写"自助找回成功"的用例
- **来源**：接口§4

#### TC-COM-009 管理员重置密码 ｜ P0 ｜ 接口+UI
- **步骤**：【UI】账号管理 → 某账号行 → "重置密码" → 确认
- **预期**：密码恢复为**身份证后 6 位**；`need_change_password=1`；该用户下次登录被要求改密
- **来源**：手册§二·七、接口§2.2

#### TC-COM-010 个人信息读取 ｜ P1 ｜ 接口+UI
- **步骤**：`GET /api/user/profile`；【UI】个人中心
- **预期**：返回 name/userNo/phone/department/role/roleLabel/className；UI 显示一致
- **来源**：接口§2.1

#### TC-COM-011 修改绑定手机号 ｜ P1 ｜ 接口
- **步骤**：`POST /api/user/change-phone`，依次：格式错、密码错、与原号相同、已被占用、正常
- **预期**：400 / 400 / 400 / 409 / 200
- **补充**：成功后 `students.phone` 或 `teachers.phone` 应同步更新

#### TC-COM-012 上传头像大小限制 ｜ P2 ｜ 接口
- **步骤**：提交 >400KB 的 base64
- **预期**：400 `头像过大，请压缩后再上传`

#### TC-COM-013 切换账号保留多账号 ｜ P1 ｜ UI
- **步骤**：个人中心 → 切换账号，依次登录 5 个不同角色账号
- **预期**：最多保存 5 个；可快速切回，无需重新输密码
- **来源**：手册§一·四、FAQ Q24

#### TC-COM-014 退出登录 ｜ P0 ｜ UI
- **步骤**：个人中心 → 退出登录
- **预期**：回到登录页；当前标签会话结束（其他标签不受影响）

#### TC-COM-015 小智按角色给快捷操作 ｜ P2 ｜ UI
- **步骤**：分别以学生/教师/管理员登录，打开右下角小智
- **预期**：快捷按钮按角色不同（学生：看成绩/看课表/看进度/我的课程；教师：我的课程/课程表/评价管理/学生进度；管理员：切换学院/课程管理/班级管理/学生详情）
- **来源**：手册§一·五

#### TC-COM-016 小智导航跳转 ｜ P1 ｜ UI
- **步骤**：对小智说"帮我看成绩"
- **预期**：目标唯一时**直接跳转**到成绩页，回复含"思路摘要"与来源标记（`LLM 决策` 或 `本地兜底`）
- **来源**：手册§一·五

#### TC-COM-017 小智追问确认 ｜ P2 ｜ UI
- **步骤**：输入一个目标不唯一的指令
- **预期**：列出候选按钮，点击其一后跳转

#### TC-COM-018 小智只导航不改数据 ｜ P1 ｜ UI
- **步骤**：让小智"帮我提交作业"/"帮我改成绩"
- **预期**：**不做数据变更**，只导航或给文字说明
- **来源**：手册§一·五 提示

#### TC-COM-019 待办跨设备保留 ｜ P1 ｜ 接口+UI
- **步骤**：
  1. 【UI】勾选完成一条待办
  2. 清除浏览器 `sessionStorage`，用**同一账号**重新登录
- **预期**：该待办的完成状态**保留**；被删除的待办不复活
- **补充**：接口层 `POST /api/todos/sync` → 重登 `GET /api/todos` 应回读一致
- **来源**：接口§2.7

  2. 【教师】我的课程看到该课程 → 导入学生并分组 → 上传课程标准 → 配置权重 → 新建任务 → 上传工单
  3. 【学生】我的课程看到该课程 → 看课程标准 → 做工单 → 提交 → 填自评/互评 → 评教 → 传素质成果
  4. 【教师】批改工单 → 给素质评价打分 → 录入笔试/项目成绩
  5. 【学生】查看综合评价、成绩查询、能力雷达
- **预期**：每步数据正确传递；最终学生端成绩与教师端录入一致
- **来源**：手册全篇

#### TC-E2E-002 排课驱动课表 ｜ P0 ｜ UI
- **步骤**：管理员新增排课 → 教师端"课程表"与学生端"我的课表"分别查看
- **预期**：两端均出现该排课
- **来源**：手册§二·九 提示

#### TC-E2E-003 课程标准三端同步 ｜ P1 ｜ UI
- **步骤**：教师上传 → 学生端 & 企业导师端查看
- **预期**：三端一致

#### TC-E2E-004 企业导师参与评价 ｜ P1 ｜ UI

- **预期**：导师评价按权重计入总成绩；教师端综合评价反映该部分

#### TC-E2E-005 账号入库 → 首登 → 干活 ｜ P0 ｜ UI
- **步骤**：管理员入库新学生 → 该生用初始密码登录 → 被强制改密 → 进入工作区
- **预期**：全链路通；改密后 `need_change_password` 置 0

#### TC-E2E-006 评价写入驱动成绩明细 ｜ P0 ｜ 接口

## 8. 手册与实现不一致 — 专项

> **本组用例的目的是"确认已知差异"，不是"验证功能"。**
> 期望值以接口文档 §4 为准。这些差异**要么改手册、要么补实现**，不能按手册直接判"失败"。

#### TC-DIFF-001 初始密码规则 ｜ P1 ｜ 接口
- **步骤**：新建账号，查看 `initialPassword`
- **预期**：**身份证后 6 位**（末位 X 大写，保留前导 0）
- **差异**：手册账号表的 `666666/222222/...` 是历史数据，**不是规则**
- **处理建议**：改手册

#### TC-DIFF-002 忘记密码无自助找回 ｜ P1 ｜ UI
- **预期**：**后端无找回接口**；只能走管理员重置
- **处理建议**：删手册该条 或 补实现

#### TC-DIFF-003 排课无冲突检测 ｜ P2 ｜ UI
- **预期**：**后端无冲突检测**，手册的"冲突"标记无实现
- **处理建议**：确认前端是否实现；都没有则删手册该条

#### TC-DIFF-004 权重合计不校验 ｜ P1 ｜ 接口
- **预期**：接口层**接受**任意合计值
- **处理建议**：决定是否补后端校验

#### TC-DIFF-005 任务锁定与截止时间未进手册 ｜ P1 ｜ UI
- **预期**：代码有**完整实现**（锁定/截止/互斥），手册只字未提
- **处理建议**：**补手册**

#### TC-DIFF-006 问卷编辑入口未进手册 ｜ P2 ｜ UI
- **预期**：`questionnaire` 接口齐全，但手册未描述在哪配置
- **处理建议**：确认前端是否有入口

#### TC-DIFF-007 企业导师端"只读"仅前端实现 ｜ P1 ｜ 接口
- **步骤**：用 mentor token 调教师写接口（如 `POST /api/projects`）
- **预期**：**接口层不拦截**（手册§五的"只读"只是前端隐藏按钮）
- **处理建议**：若要真只读，需后端补校验

#### TC-DIFF-008 分层测试闸门在前端 ｜ P1 ｜ 接口
- **预期**：接口层**可绕过**"第一节课结束后开启"
- **处理建议**：如需强约束，后端补闸门

#### TC-DIFF-009 分层测试回传正确答案 ｜ P2 ｜ 接口
- **预期**：`details[].correctAnswer` **确实返回**
- **处理建议**：若允许重考，需移除该字段

#### TC-DIFF-010 素质评价打分不可撤销 ｜ P1 ｜ 接口
- **预期**：重复打分 409，**无撤销接口**
- **处理建议**：如需纠错，补"撤销打分"

#### TC-DIFF-011 未挂载代码 ｜ P2 ｜ 接口
- **步骤**：调 `/api/tasks`、`/api/teaching/todos`
- **预期**：**404**（死代码，不在测试范围）
- **处理建议**：删除或明确标注

#### TC-DIFF-012 两套登录 id 空间 ｜ P1 ｜ 接口
- **步骤**：分别用 `/api/auth/login` 与 `/api/user/login` 取 token，各查一次学生
- **预期**：`id` 语义不同（前者 students 主键，后者 users 主键）——**不可混用**
- **处理建议**：废弃旧接口

#### TC-DIFF-013 素质成果文件上限 2MB vs 720KB ｜ P1 ｜ UI
- **步骤**：上传一个 1MB 的文件到素质成果
- **预期**：**被拒绝**（实现是 720KB），并在界面提示实际上限
- **差异**：手册§四·六 写"单个文件不超过 2MB"，**实现是 720KB**（见接口§1.5 的推导）
- **处理建议**：改手册为 720KB；或由运维放开 nginx 后同步调大三处（前端基准 / Express / nginx）

## 9. 边界与异常

#### TC-BND-001 课程学生数为 0 时加学生 ｜ P1 ｜ UI
- **步骤**：教师进新课（"共 0 名学生"）→ "学生管理" → "新增学生"
- **预期**：可从系统总库搜索加入；学生不在总库时需先由管理员入库
- **来源**：FAQ Q5

#### TC-BND-002 班级有学生时不可删 ｜ P1 ｜ 接口
- **预期**：`DELETE /api/classes/:id` 返回 **409 CLASS_HAS_STUDENTS**

#### TC-BND-003 班级重名 ｜ P2 ｜ 接口
- **预期**：创建/改名时重名 → **409 CLASS_EXISTS**

#### TC-BND-004 不存在的资源 ID ｜ P1 ｜ 接口
- **步骤**：对不存在的 id 调 PUT/DELETE
- **预期**：**404**

#### TC-BND-005 不存在的路由方法 ｜ P2 ｜ 接口
- **步骤**：`POST /api/teachers`（该资源**没有 POST**）
- **预期**：**404**（不是因为权限，而是方法不存在）——**不要误判成"权限被拦"**

#### TC-BND-006 超大请求体 ｜ P1 ｜ 接口
- **步骤**：绕过前端，直接提交超过 **1 MiB**（nginx `client_max_body_size` 默认值）的 JSON
- **预期**：**413**，中文提示（不要只显示"请求失败(413)"）
- **说明**：真正的网关瓶颈是 **1 MiB**；Express 设的 2MB 刻意在其之上，**不会先触发**。
  文件类上传前端会先在 720KB 处拦截，见接口§1.5

#### TC-BND-007 请求体非法 JSON ｜ P2 ｜ 接口
- **预期**：400 `请求体格式错误，无法解析`

#### TC-BND-008 并发派号不重复 ｜ P1 ｜ 接口
- **步骤**：并发创建 20 个账号
- **预期**：学号/工号**无重复、无跳号冲突**

#### TC-BND-009 重复同步待办 ｜ P1 ｜ 接口
- **步骤**：连续两次 `POST /api/todos/sync` 传不同列表
- **预期**：第二次的列表成为最终状态（**覆盖式**）

#### TC-BND-010 待办脏数据被过滤 ｜ P2 ｜ 接口
- **步骤**：sync 传含无 `id` 或无 `title` 的行
- **预期**：脏行被**丢弃**，不计入 `synced`

#### TC-BND-011 待办非数组入参 ｜ P2 ｜ 接口
- **预期**：400 `todos 必须是数组`

#### TC-BND-012 大文件上传导致 MySQL 断连 ｜ P1 ｜ 接口
- **步骤**：上传接近上限的文件
- **预期**：应返回**可读错误**，而非"服务器已重启"
- **补充**：若 MySQL `max_allowed_packet` 不足，会在 DB 层断连（后端启动日志会告警）

#### TC-BND-013 分页边界 ｜ P2 ｜ 接口
- **步骤**：`page=0`、`pageSize=0`、`pageSize=1000`
- **预期**：page 最小 1；pageSize 被夹在 1–上限之间

#### TC-BND-014 Excel 导入格式错误 ｜ P1 ｜ UI
- **步骤**：上传 .txt 或列名不符的 Excel
- **预期**：给出可读失败原因
- **来源**：FAQ Q14

#### TC-BND-015 同一电脑多账号演示 ｜ P2 ｜ UI
- **预期**：切换账号最多保留 5 个，数据不丢
- **来源**：FAQ Q24
